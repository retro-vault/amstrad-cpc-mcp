# 6845 CRTC notes

## Supported CPC types

The command line exposes the CPC community's conventional CRTC types 0, 1 and
2. These names describe observable compatibility families, not a promise that
every board used one exact manufacturer marking.

| Option | Core family | Important modeled distinction |
|---:|---|---|
| 0 | HD6845S-compatible (`UM6845` in the core) | readable R12-R17, programmable VSYNC width |
| 1 | UM6845R | write-only R12/R13, R31 reads `0xff`, fixed VSYNC width |
| 2 | MC6845 | Motorola read rules, zero horizontal width means 16 |

All types expose separate state instances and may be selected on any classic
model for software compatibility testing.

## Bus and counters

The CRTC is selected when A14=0. A8 selects address/status or register data; A9
selects write or read in CPC wiring. Conventional ports are BCxx through BFxx,
but all aliases satisfying those address lines work and can overlap other CPC
devices.

Registers R0-R9 define horizontal total/display/sync, vertical total/adjust,
vertical display/sync, interlace/skew and maximum raster. R12/R13 provide the
display start address. Internal horizontal, character-row, raster, sync-width
and memory-address counters advance once per 1 MHz CCLK. MA0-MA13, RA0-RA4,
DE, HSYNC and VSYNC feed the Gate Array every tick.

Register totals use the 6845 “value plus one” convention. Register writes also
update coincidence conditions against live counters, which is important to
raster software that rewrites geometry during a line.

## Stock PAL geometry

The firmware programs the familiar 64-character line, 39 displayed-character
endpoint, eight scanlines per character row and 312-line PAL frame. Combined
with the Gate Array this yields 79,872 Z80 T-states per standard frame and the
768×272 visible overscan returned by MCP.

## Conformance boundary

Normal firmware screens, scrolling addresses, mode switches and SHAKER's menu
render correctly. Register masks/readability and several type-dependent sync
width rules are modeled.

The current core does not yet completely implement interlace, display/cursor
skew, cursor, light pen, or the full type-dependent behavior of vertical-total
adjust and extreme mid-frame register updates. The MCP frame counter also uses
the fixed standard PAL interval even if a program deliberately constructs a
nonstandard CRTC frame. These omissions are explicitly tracked because SHAKER
contains tests beyond the original data-sheet contract. Official SHAKER
approval has not been requested or claimed.
